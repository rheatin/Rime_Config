# 「分应用中英文自动切换」完全指南 (Windows 小狼毫 / Weasel + macOS 鼠须管 / Squirrel)

> 目标：**除了聊天软件和浏览器，其它程序一律默认英文。**

---

## 1. 为什么 Mac 上能用、Windows 上感觉没生效

两边看起来是同一个 `app_options` 配置项，但**触发时机完全不同**，这是所有困惑的根源。
以下结论来自直接阅读 [weasel](https://github.com/rime/weasel)、[librime](https://github.com/rime/librime)、
[squirrel](https://github.com/rime/squirrel) 源码，不是猜测。

| | macOS (鼠须管 Squirrel) | Windows (小狼毫 Weasel) |
|---|---|---|
| 匹配键 | **Bundle ID**（`com.google.Chrome`） | **宿主进程 exe 名**（`chrome.exe`） |
| 重新套用时机 | **每次前端 App 变化**都会重新套用 | **只在 Rime 会话被创建时套用一次** |
| 会话粒度 | 每个 App 一个 IMK controller + 一个会话 | 每个 App 的 UI 线程一个会话 |
| 是否响应「获得焦点」 | 是 | **否**（`FocusIn()` 只更新 UI，不重新套用配置） |
| 额外加成 | macOS 自身会记住每个 App 的输入源 | 无 |

Squirrel 源码 `sources/SquirrelInputController.swift`：

```swift
if let app = client?.bundleIdentifier(), currentApp != app {
  currentApp = app
  updateAppOptions()      // ← 每次切换 App 都重新套用
}
```

Weasel 源码 `RimeWithWeasel/RimeWithWeasel.cpp`：

```cpp
void RimeWithWeaselHandler::FocusIn(DWORD client_caps, WeaselSessionId ipc_id) {
  DLOG(INFO) << "Focus in: ipc_id = " << ipc_id;
  if (m_disabled) return;
  _UpdateUI(ipc_id);
  m_active_session = ipc_id;     // ← 只记录「谁在前台」，不重新套用 app_options
}
```

`_ReadClientInfo()`（真正套用 `app_options` 的地方）**只被 `AddSession()` 调用**，
而 `AddSession()` 只在新建会话时发生。所以：

> **Windows 上 `app_options` 决定的是「这个 App 新建会话时的初始状态」，
> 而不是「切到这个 App 就变成这个状态」。**

官方文档的措辞也印证了这一点：「在指定的應用程序中，改變輸入法的**初始**轉換狀態」。

## 2. Windows 上「分应用不独立」的几个真实原因

1. **手动切换会全局串味（本次已修掉的元凶）**
   小狼毫 0.17.x 自带的 `default.yaml` 里：

   ```yaml
   switcher:
     save_options:
       - ascii_mode      # ← 罪魁祸首
       - full_shape
       ...
   ```

   librime 的 `Switcher::RestoreSavedOptions()` 会在**每个新会话**里执行：

   ```cpp
   for (const string& option_name : save_options_) {
     if (user_config_->GetBool("var/option/" + option_name, &value))
       engine_->context()->set_option(option_name, value);   // ← 盖掉方案里的 reset
   }
   ```

   于是：只要你在**任意一个** App 里用**方案菜单**切过一次中/英，这个状态就被写进
   `%APPDATA%\Rime\user.yaml` 的 `var/option/ascii_mode`，之后**所有** App 的新会话都会
   先恢复到它，`rime_frost` 里的 `switches/@0/reset: 1` 被直接覆盖 —— 表现就是
   「完全不按 App 走」。

2. **`app_options` 只在会话创建时套用。** 配置改完必须让 App **重建会话**才会生效：
   重新部署、重启该 App，或在任意输入框里重新输入一次。

3. **键名必须是宿主进程 exe 名。** 不是窗口标题、不是 AppID、不是子进程。
   控制台类程序要同时写壳和宿主（官方默认值里 `cmd.exe` 和 `conhost.exe` 是成对出现的）。

4. **值只认布尔量。** Weasel 内部类型就是 `std::map<std::string, bool>`；
   只有 `ascii_mode`、`inline_preedit`、`vim_mode` 三个键有效，写别的会被静默忽略。

5. **在 App 内切换输入方案（F4 / Ctrl+`）会按方案的 `reset` 重新初始化 `ascii_mode`，
   而 Weasel 此时不会重新套用 `app_options`。** 这是 0.17.x 的已知行为，没有配置项可改。

6. **`global_ascii` 是「分应用」的反面。** 必须保持 `false`（默认值），
   设成 `true` 会让所有会话强制同步同一个状态。

## 3. 本仓库目前的实现（正确姿势）

**核心思想：不写黑名单，而是让「未列出的 App」自动回落到英文。**

小狼毫没有「全局默认 ascii_mode」这个配置项，但 `switches/@0/reset` 就是它：

```
未列出的 App  →  没有任何 app_options 被套用  →  回落到方案 reset
              →  rime_frost.custom.yaml 里 switches/@0/reset: 1  →  英文 ✅
列出的 App    →  app_options 套用 ascii_mode: false  →  中文 ✅
```

所以只需要维护一份**中文白名单**（聊天软件 + 浏览器）。仓库里同时把常用工具
显式钉成英文，纯粹是为了以后万一改了 `reset` 也不会翻车。

### 3.1 `rime_frost.custom.yaml` — 全局默认英文（Mac / Windows 通用）

```yaml
patch:
  "switches/@0/reset": 1        # ascii_mode 的初始值 = 1 = 英文
```

> ⚠️ `switches` 列表里 `ascii_mode` 必须是**第 0 项**。当前 `rime_frost` 方案满足。

### 3.2 `default.custom.yaml` — 防止全局串味（**Windows 关键修复**）

```yaml
patch:
  switcher/save_options:
    - full_shape
    - ascii_punct
    - traditionalization
    - emoji
    - chinese_english
    - chaifen
    - mars
    - pin_cand
    # 注意：故意不含 ascii_mode
```

去掉 `ascii_mode` 之后：

* 每个 App 的初始状态**严格**由 `app_options` / `reset` 决定，不再被历史操作污染；
* 代价：在同一 App 内手动切到的中/英状态不再跨会话保存。想让它「记住」，
  就把它写进 `app_options`（这正是「分应用」的本意）。

### 3.3 `weasel.custom.yaml` — 中文白名单

```yaml
patch:
  app_options:
    # 聊天与通讯（自动中文）
    wechat.exe:      { ascii_mode: false }
    weixin.exe:      { ascii_mode: false }   # 微信 4.x
    qq.exe:          { ascii_mode: false }
    discord.exe:     { ascii_mode: false }
    ...
    # 浏览器（自动中文）
    chrome.exe:      { ascii_mode: false }
    msedge.exe:      { ascii_mode: false }
    firefox.exe:     { ascii_mode: false }
    ...
```

## 4. 改完之后必须做的事

```powershell
# 1. 重新部署（等价于托盘菜单「重新部署」）
& "C:\Program Files\Rime\weasel-0.17.4\WeaselDeployer.exe" /deploy

# 2. 验证部署结果确实合并进去了（官方推荐的排查手段）
Select-String "$env:APPDATA\Rime\build\weasel.yaml" -Pattern 'app_options' -Context 0,4
```

> 运行时的 Rime 读的是 **`%APPDATA%\Rime\build\` 里编译后的配置**，不是仓库里的源文件。
> 不重新部署 = 改了也没用。这一点在 0.17.x 尤其重要：该版本**不会**在服务启动时自动部署。

然后让每个 App **重建会话**：重新部署后所有会话都会被清掉，
在新 App 里点一下输入框敲一个字就会重新套用。若某个 App 没变化，重启该 App。

### macOS (Squirrel / 鼠须管)

```bash
# 确定性重新部署（不依赖 Squirrel 进程当时是否在运行）
bash deploy.sh
```

> ⚠️ **不要只依赖 `Squirrel --reload`。**
> `--reload` 只是向**正在运行的** Squirrel 进程广播一个分布式通知
> (`SquirrelReloadNotification`)。如果 Squirrel 当时没在运行
> （例如当前选中的输入源是 ABC），这条通知会被静默丢弃 —— 部署永远不会发生。
>
> 后果有两层，且都会表现为「不能输入中文」：
>
> 1. `~/Library/Rime/build/` 缺失 → librime 回落到
>    `SharedSupport/build/` 里的原版 `luna_pinyin`，
>    自己的方案 / 词库 / Lua / snippets 全部「消失」；
> 2. `build/squirrel.yaml` 缺失 → `config_open("squirrel")` 返回**空配置** →
>    `app_options` 白名单整体失效 → 配合 `switches/@0/reset: 1`，
>    **所有 App 都以英文启动**，无论是否在白名单里。

`deploy.sh` 依次做四件事，每步都校验产物：

| 步骤 | 命令 | 产物 |
|---|---|---|
| 0. 同步仓库配置 | `cp` 仓库里的 `*.custom.yaml` / `lua/` / 依赖词典到 `$RIME_DIR` | — |
| 1. 编译方案与词库 | `rime_deployer --build` | `build/*.schema.yaml`、`build/default.yaml` |
| 2. 生成前端配置 | 拉起 Squirrel 后 `--reload` | `build/squirrel.yaml` |
| 3. 校验 | 检查上述文件 + 依赖词典是否编译 | — |

> `build/squirrel.yaml` **只能**由前端的 `config_file_update` 任务编译
> （`deploy_config_file("squirrel.yaml", "config_version")`），
> `rime_deployer --build` 不产出它 —— 这就是第 2 步必须经过前端的原因。

> 第 0 步同样关键：仓库 (Rime_Config) 是配置的**权威来源**，
> `~/Library/Rime` 只是运行目录。少了这一步，改了仓库里的
> `squirrel.custom.yaml` 也不会生效 —— 部署用的仍是用户目录里的旧副本。

**排查用命令**

```bash
# 运行时日志（含 "missing input schema" / Lua 报错）
ls -t "$(getconf DARWIN_USER_TEMP_DIR)/rime.squirrel/"*.INFO.* | head -1 | xargs grep -E "^E|^W"

# 确认 app_options 真的编译进去了
grep -A3 "app_options:" ~/Library/Rime/build/squirrel.yaml | head
```

### 字体（macOS）

字体**不是**下载来的 —— `fonts/` 目录里的四个文件直接 committed 在仓库里
（`SourceHanSerifSC/TC-Heavy.otf`、`SymbolsNerdFont{,Mono}-Regular.ttf`），
`install.sh` 第 8 步把它们拷进 `~/Library/Fonts`。

两个静默失效的坑：

**1. `style/font_face` 会让配色方案的字体永不生效**

SquirrelTheme 的取值逻辑是：

```swift
var fontName = config.getString("style/font_face")   // 先取 style
...
fontName ?= config.getString("\(prefix)/font_face")   // ?= 不覆盖已有值
```

也就是说 **`style/font_face` 只要存在，配色方案里的 `font_face` 就永远是死代码**。
要换字体就改 `preset_color_schemes/*/font_face`，**不要**在 `style:` 下设 `font_face`。

**2. 字体名必须用 PostScript 名**

`font_face` 是逗号分隔的字体列表，Squirrel 逐个用
`NSFontDescriptor(fontAttributes: [.name: name])` 解析。
家族名（`Symbols Nerd Font Mono`）和 PostScript 名（`SymbolsNFM`）都能解析，
但指向同一款字体 —— 同时写会在回退链里产生重复项。
本仓库统一使用 PostScript 名：

```
SourceHanSerifSC-Heavy, SourceHanSerifTC-Heavy, PingFangSC-Regular, SymbolsNFM, SymbolsNF
```

顺序即回退链：中文 → 思源宋体 → 苹方 → Nerd Font Mono → Nerd Font。
`SymbolsNFM` 必须排在 `SymbolsNF` 前面（Powerline 等私有区字形只有 Mono 版有）。

**3. 字体装完可能没被系统收录**

字体拷进 `~/Library/Fonts` 后，`fontd` 不一定立刻收录它们。
实测症状：文件在磁盘上、`system_profiler` 也能看到，
但 `CTFontManagerCopyAvailablePostScriptNames()` 里查不到 ——
于是 CoreText 解析 `font_face` 时静默回落到默认字体，**没有任何报错**。
`install.sh` 第 8.1 步会 `touch` 字体并重启 `fontd` 强制全量重扫。

验证字体是否真的可用：

```bash
# PostScript 名是否已注册（四个都应 REGISTERED）
python3 - <<'PY'
import ctypes, ctypes.util
ct = ctypes.cdll.LoadLibrary(ctypes.util.find_library("CoreText"))
cf = ctypes.cdll.LoadLibrary(ctypes.util.find_library("CoreFoundation"))
cf.CFArrayGetCount.argtypes=[ctypes.c_void_p]; cf.CFArrayGetCount.restype=ctypes.c_long
cf.CFArrayGetValueAtIndex.argtypes=[ctypes.c_void_p,ctypes.c_long]; cf.CFArrayGetValueAtIndex.restype=ctypes.c_void_p
cf.CFStringGetCString.argtypes=[ctypes.c_void_p,ctypes.c_char_p,ctypes.c_long,ctypes.c_uint32]
ct.CTFontManagerCopyAvailablePostScriptNames.restype=ctypes.c_void_p
arr=ct.CTFontManagerCopyAvailablePostScriptNames(); n=cf.CFArrayGetCount(arr)
names=set()
for i in range(n):
    p=cf.CFArrayGetValueAtIndex(arr,i); b=ctypes.create_string_buffer(512)
    if cf.CFStringGetCString(p,b,512,0x08000100): names.add(b.value.decode())
for w in ["SourceHanSerifSC-Heavy","SourceHanSerifTC-Heavy","SymbolsNF","SymbolsNFM"]:
    print(f"  {w:26s} {'REGISTERED' if w in names else 'MISSING'}")
PY
```

## 5. 如何新增一个 App

### Windows (Weasel / 小狼毫)

```powershell
# 扫出还没收录的程序（正在运行的 / 已安装的）
pwsh -File tools\New-AppOptions.ps1
pwsh -File tools\New-AppOptions.ps1 -RunningOnly
```

### macOS (Squirrel / 鼠须管)

```bash
# 扫出还没收录的程序（正在运行的 / 已安装的）
./tools/New-AppOptions.sh
# 仅扫描当前运行中的前台与状态栏应用
./tools/New-AppOptions.sh -r
# 生成完整 YAML 片段文件
./tools/New-AppOptions.sh -w
# 智能合并追加进 squirrel.custom.yaml 并自动同步重载
./tools/New-AppOptions.sh -a
```

脚本会打印可直接粘贴的 YAML 片段（对终端程序自动附带 `no_inline: true`）。判断规则很简单：

* 这个 App 里我需要打中文 → `ascii_mode: false`
* 不需要（默认就是英文）→ 什么也不用写
* 想长期钉死英文 → `ascii_mode: true`（终端加上 `no_inline: true`）

## 6. 已知限制（0.17.x，无法用配置绕过）

| 限制 | 说明 |
|---|---|
| 不支持通配符 / 正则 | 只有精确 exe 名匹配（上游 open issue [#1544](https://github.com/rime/weasel/issues/1544)） |
| 无法「锁定」某个 App 禁止切中文 | 在 App 内按 Shift / Ctrl+Space 仍然能切到中文 |
| 多线程 App 可能有多个会话 | 同一个 App 的不同线程可能持有不同状态 |
| 切换输入方案会重置状态 | F4 / Ctrl+` 切方案后按方案 `reset` 重新初始化，且不会重新套用 `app_options` |
| 生效需要重建会话 | 见第 4 节 |

如果确实需要「某个 App 永远不能打中文」，那只能改用 schema 层面隔离
（例如为纯英文场景单独留一个 `switches/@0/reset: 1` 且把
`ascii_composer/switch_key` 设为 `noop` 的方案），Weasel 的 `app_options` 做不到。

## 7. 一分钟自检清单

1. `%APPDATA%\Rime\build\weasel.yaml` 里能看到你的 `app_options` 吗？→ 没有就是没部署
2. `%APPDATA%\Rime\build\default.yaml` 的 `save_options` 里**还有 `ascii_mode` 吗**？→ 有就会全局串味
3. `%APPDATA%\Rime\build\rime_frost.schema.yaml` 里 `ascii_mode` 的 `reset` 是 `1` 吗？
4. `%APPDATA%\Rime\build\weasel.yaml` 里 `global_ascii` 是 `false` 吗？
5. 键名是不是当前进程的真实 exe 名？（任务管理器 → 详细信息 → 看「名称」列，而不是窗口标题）
6. 有没有重新部署 + 重建会话？

### macOS 追加自检

7. `~/Library/Rime/build/squirrel.yaml` 存在吗？→ **不存在 = 分应用切换整体失效**
8. `~/Library/Rime/build/squirrel.yaml` 里有 `app_options:` 吗？→ 没有就是没部署进去
9. `~/Library/Rime/build/default.yaml` 里的 `schema_list` 是你的方案吗？
   → 变成 `luna_pinyin` 说明部署没生效，跑 `bash deploy.sh`
10. `~/Library/Rime/build/` 里有没有 `rime_frost_aux.*.bin`？
    → 缺失说明 `clean.sh` 误删了依赖词典，``反查（`frost_aux`）会失效
11. 日志里有 `missing input schema` 吗？→ 有就是某个依赖词典缺失
12. 日志里有 `module 'xxx' not found` 吗？→ 某个 Lua 脚本的 `require` 依赖缺失
13. `~/Library/Rime/build/squirrel.yaml` 的 `style:` 下有 `font_face` 吗？
    → **有的话配色方案的字体永远不会生效**（见第 4 节「字体」）
14. `CTFontManagerCopyAvailablePostScriptNames()` 里查得到
    `SourceHanSerifSC-Heavy` / `SymbolsNFM` 吗？→ 查不到就是字体没被系统收录
